Conventions established by these tools and `LEGACY:narrative/art/MANIFEST.md`
(`1xy6ugTNUGaG6Ys9KQCeU9oHXoOx_QSjf`):

- **File naming:** `{kind}_{id}_{variant}_v{NNN}[_t{N}].png`
  (e.g. `battle_pose_fadyme_idle_v002.png`, `vn_bust_fadyme_quiet_pain_v002.png`,
  `bg_forest_whispering_ash_ordered_v001.png`); character sheets
  `char-{id-with-hyphens}-uomd.png`; music `{id}_v{NNN}_{loop|original}.{ogg|mp3}`
  + `.json` sidecar; voice lines `audio/voice/<speaker_id>/<line_id>.ogg`.
- **IDs:** snake_case content ids shared with game data (`fadyme`,
  `forest_whispering_ash`, `lady_yseldra_vale`, `key_art`, `logo`).
- **Metadata:** inside the PNG (`uomd_*` tEXt chunks) for images; JSON
  sidecars for audio.
- **Status vocabulary:** `REVIEW → APPROVED | APPROVED_WITH_ISSUE | REJECTED |
  SUPERSEDED | REFERENCE | PENDING`.
- **Folders:** `art/_review/`, `art/_rejected/`, `art/_proposed/`,
  `art/brand/` (+`superseded/`, `concepts/`), `art/sheets/` (+`chibi_ref/`,
  `pending/`), `art/production/<id>/`, `art/production/locations/<id>/`,
  `audio/_review/`, `audio/_rejected/`, `audio/music/<id>/`,
  `audio/voice/<id>/`.
- **Lineage:** every image records its reference images; revisions are
  `v001…`, tries `t1…`.
- **Credentials:** tools read `GOOGLE_API_KEY`/`GEMINI_API_KEY` from env or
  `narrative/.secrets/google_api.env`. In this environment the proxy injects
  the key, so the tools need a small adaptation (no key file).

Assessment: **REUSABLE / NEEDS_REFACTOR (minor)**. This is exactly the
pipeline the active `docs/UOMD_ASSET_PIPELINE.md` asks for and says must be
found before inventing anything. Adopt it under `narrative/` with:
key handling adapted to the proxy, paths re-rooted at `narrative/`, and a

tooling. Content→asset traceability via `content/visual_assets_part1.json` and
`content/character_visuals_part1.json` (to be audited with `LEGACY:content/`).
