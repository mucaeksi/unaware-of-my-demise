## Game client (`apps/unity/` — Decision D-31, supersedes historical D-23/D-25)
- **Unity 6 LTS (`6000.0.x`, C#, Universal Render Pipeline 2D + UI Toolkit / TextMeshPro)** owned and implemented exclusively by **Claude Opus 5.5** per [docs/handoff/CLAUDE_OPUS_UNITY_HANDOFF.md](handoff/CLAUDE_OPUS_UNITY_HANDOFF.md), authored in the 1920×1080 landscape reference frame with `Screen.safeArea` adaptive reflow, reduced-motion/flash preferences, and 8 modular `.asmdef` assemblies (`Uomd.Shared`, `Uomd.ContentSchema`, `Uomd.Patch`, `Uomd.Economy`, `Uomd.Story`, `Uomd.Combat`, `Uomd.Game`, `Uomd.Native`).
- **28 Scenes:** `Splash` → `Studio` → `Boot` → `Title` → `Prologue` → `Story` → `Battle` → `Finish` → `Home` (World Map Hub) / `Chapters` / `Roster` / `Character` / `Gear` / `Team` / `Summon` / `Recruit` / `Shop` / `Tasks` / `Deeds` / `Trials` / `Profile` / `Mail` / `Library` / `Account` / `Operations` / `Purchases` / `PatchBar` / `ContentPanel`. Everything the scenes show comes from `ContentService` (signed R2 patch overlay over `StreamingAssets/uomd_base`).
- **Handed-over legacy reference (`apps/game`):** The previous TypeScript web client is retained in the repository strictly as a read-only behavioral and test oracle until Unity Phases `U-1..U-5` reach 100% parity, after which it is archived into `archive/legacy-web-era` (Phase `U-6`).
- **Battle replay parity:** Unity C# combat (`Uomd.Combat`) uses the generated `Mulberry32Rng` and `RoundHalfUp` (`UomdCorePrimitives.g.cs`) so that client battle logs match the server's `/api/v1/battles/verify` re-simulation bit-for-bit.
- **Audio & Media:** All remaining and future art, BGM (Lyria 3.5), and Japanese VO (Gemini TTS) assets are generated by **Claude Opus 5.5** exclusively via the **Google Gemini API**.

## Backend (`apps/api`)
- **Game Worker** — `GET /api/v1/health` (D1 + R2 probes), `/content/channels/:channel/manifest` (signed, ETag),
  `/content/objects/:sha256` (immutable; only objects of a *published* release on that channel), `/characters`,
  `POST /battles/verify` (rate-limited, server re-simulation, audit row).
- **Control Center Worker** — Access JWT verified in code (RS256, issuer = team domain, audience = app), identity → role in
  `admin_users` (viewer/operator/owner), optimistic concurrency on edits, append-only `audit_log` (D1 triggers), asset
  catalog with provenance, release pipeline (upload → validate → draft → sign → publish / rollback / kill switch).
  First owner: `INSERT INTO admin_users (email, role, created_by) VALUES ('<you>', 'owner', 'manual');` (no secret involved).
- **D1** (`migrations/0001_core.sql`, `0002_economy_ledger.sql`): content releases/objects/pointers, audit, characters,
  assets, battle audit, rate counters, players/wallets/ledger. Ledger = unique idempotency key + `CHECK (balance >= 0)` in a
  single `batch()` transaction; verified with 50 concurrent debits and 20 concurrent identical requests.
- **R2**: content-addressed objects only. Nothing financial lives in object storage.

## Environments
`dev` and `staging` have separate D1 databases, R2 buckets, Worker names and rate-limit namespaces. There is **no
production environment definition yet** (needs owner approval); legacy production resources are untouched.
