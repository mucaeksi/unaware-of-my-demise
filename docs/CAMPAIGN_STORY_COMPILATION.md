# Part I story compilation

`npm run build:campaign` compiles the ordered main story from `narrative/02_Main_Story/story_script_part1_manifest.json` and its seven canonical chapter files. The runtime snapshot continues to supply stage mechanics, rewards, drops, loans and unit definitions. It does not override dialogue or scene direction.

The campaign patch contains 51 main-story entries: 35 battles and 16 standalone scenes. Its 88 dialogue files contain 419 unique line IDs: 414 pre/post/standalone lines and five boss-phase lines. Alongside the three embedded tutorial nodes, the index has 54 nodes in eight chapters. Every main-story node requires its immediate predecessor; the opening has no prerequisite. Existing battle node IDs and authored reward/drop/Ration values are preserved. Chapters 2 and 5 use their canonical names; their mapping to the snapshot is checked against the exact stage IDs.

Compilation preserves exact English text, line IDs, speaker IDs/display names, emotion and Japanese voice-track labels. Each output scene identifies its canonical source file and SHA-256; the index declares all eight source files, chapter/entry order, scene links and line order. Compiler tests compare the generated files directly with repository canon. The shared publication/device validator checks the declaration against linked scenes, provenance, prerequisite order and actual encounter boss phases. A signed coverage declaration is not an independent copy of repository canon on the device.

Canonical chapter-1 music prefixes and chapter-7 after-battle music directions take precedence over the drifted snapshot. Direction and cue prose remains bounded production metadata, never executable instructions. Missing production audio is silent (`music: stop`); Japanese voice tags do not synthesize audio. Only supplied portraits are shown. Eleven additional locations use the existing generic gradient placeholder method pending approved production art. The 107 embedded entry dialogue lines and current manual tutorial controls are untouched; historical automatic-combat/portrait-tap tutorial prose is not converted into runtime commands.

Phase interludes compile to a finite encounter binding. `phase_N_break` enters phase N's successor, while `phase_N_ward` names phase N being entered. Both authored Construct interludes resolve to `boss_eclipse_construct/aether_ward`, preserving all five lines in authored order. Missing or ambiguous bosses/phases fail compilation. The reader pauses battle presentation until each scene ends, then resumes it and restores supplied battle music. It does not add combat actions or change RNG, rewards or authoritative replay.

Locked chapter/card titles use generic placeholders so future reveal titles cannot appear in the menu. Chapter progress remains account-authoritative for signed-in players. Standalone completion uses the durable reward-free operation introduced in R07-C1. Post-battle/checkpoint resume is still R09 work; a battle clear alone is not proof that its post-scene was read. Reusable companion/codex/event gates, First Oath selector consumption, full chapter no-gacha acceptance and effective economic catalog authority remain separate R07/R08 work. Native and deployed acceptance is not established by browser tests.

The new strict schema fields and phase-reader support require the updated client. This slice does not establish compatibility with an older unchanged AAB; capability/version negotiation and signed-original-AAB acceptance remain R08/R18 work.
