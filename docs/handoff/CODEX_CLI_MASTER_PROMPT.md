## 6. Critical C# / Unity architecture already written

### 6.1 One bootstrap scene, routed screens

`Scripts/Scenes/UomdSceneRouter.cs` owns the `UIDocument`, safe-area root, screen host, overlay host and patch strip.
It initializes session, patch manager, API, platform bridge, audio, media catalog and entry flow, then registers controllers.
The current architecture does **not** contain 28 separate `.unity` scene files. Do not make 28 empty scenes as a substitute
for connecting real content. Add physical/additive scenes only where content streaming or authoring actually requires them.

The existing controller contract is:

```csharp
public interface IUomdScreenController
{
    UomdScreenId ScreenId { get; }
    Awaitable OnEnterAsync(VisualElement screenRoot);
    void OnTick(float deltaTime);
    void OnExit();
}
```

Navigation invalidates the previous request, calls the outgoing controller's `OnExit`, clears the host and releases
screen textures. Content changes reload catalogs before entering. `OnDestroy` exits the active controller and releases
media. Preserve the actual `UIDocument` lifecycle: router setup runs in `Start`, after the document's `OnEnable`.

All async presentation loads use a request/generation guard: capture generation before `await`, validate after it, and
invalidate on exit. Preserve these fences when adding animation, previews or dialogs. Never double-await a Unity
`Awaitable`; manage cancellation, object lifetime and the main thread explicitly.
