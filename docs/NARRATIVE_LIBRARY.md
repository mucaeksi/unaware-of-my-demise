# Canonical narrative library

`npm run build:campaign` compiles `narrative/03_Companion_Stories/character_stories_part1.json`, `narrative/05_Codex_Lore/lore_text_part1.json` (codex only) and `narrative/04_Events/events_part1.json`. Planned event folders are not live canon. The signed patch carries one `library/library_index.json`: 76 companion parts, 12 codex records and four three-scene events, 92 entries and 100 scenes. All 433 supplied dialogue line IDs/text/speakers/emotions/JP voice labels are exact. Codex prose keeps its stable codex ID and derives a `<codex_id>_text` narration ID, giving 445 library line IDs. Direction remains metadata; no prose becomes executable code. The original 51-entry/419-line main story, tutorials, numeric mechanics and rewards are unchanged.

`NarrativeGate` is a strict finite AND object: `after_node`, `owned_character`, `after_entry`. Stage gates map canonical `X-Y` to the existing battle node `stage_X_Y` and require a positive star result for that exact ID; a zero-star clear or a later stage never substitutes. Companion parts require the declared character except Mahmut/Fadyme, plus the preceding part’s durable clear. Parts and groups retain canonical order. Codex premise entries have an empty gate. Events require their authored stage and play their three scenes in order; this is their narrative interpreter, not a schedule or reward system.

The shared effective-content validator checks known battle/character/previous-entry references, companion order/ownership, cross-main entry/scene/line collisions, declared source hashes, exact line coverage and all embedded StoryScene commands/art references. Draft/publication and device activation run that validator. Exact repository-source comparison belongs to compiler tests; a signed source declaration does not independently prove repository canon on a device. Twenty-six additional locations use the existing generic gradient placeholders. Codex uses the supplied forest backdrop as provisional presentation. Only supplied portraits appear; missing production music/VO is silent.

`GET /api/v1/library?releaseId=…` returns only unlocked cards with read/replay status. Locked titles, scene text and gates are omitted. `GET /api/v1/library/:id?releaseId=…` rechecks the authenticated account, published channel/release authority and all gates before returning the entry. Both routes are rate limited and no-store. Facts are read in one D1 batch using declared IDs only, with chunks of 99 IDs plus the player parameter. Signed downloadable content is not secret storage; these are player presentation gates, not DRM.

`POST /api/v1/progress/story` accepts library IDs through the existing strict payload and immutable exact-input journal. No new migration is required. The atomic reward-free completion repeats the account/release/stage/ownership/previous-part fences, writes one zero-star/one-clear progress marker and the original result. Journal faults or changed eligibility roll everything back. Concurrent/repeated reads keep one clear; a committed result remains recoverable after a killed release. Wallet, grants, Ration and tasks are not changed.

Home opens Archive. The existing Gothic hub/reader renders only server-approved data, provides tabs/paging, loading/empty/unavailable/retry states and explicit return navigation without marking an unfinished read. A completion waits for confirmation and exposes retry/back above the reader HUD. The generic durable journal/Saved Actions/status recovery supports library completions. Reader loads and callbacks are fenced against scene shutdown/account changes; selecting another account closes its previous active reading. Mid-scene/event checkpoint restoration is still R09 work.

All 764 application/tool tests, lint/typecheck, campaign/game/admin builds and 46 adapters pass. The real local-Worker browser matrix passes 14 cases with all 25 migrations; two final desktop/touch-phone library cases also pass after explicit return navigation and save-error render-order checks. They cover canonical codex/companion/event readers, same-stage part order, committed-but-lost save/reload/status recovery with zero extra POSTs, early exit without a completion marker, clickable error-back controls above the HUD and account-change closure/isolation. Premise, reader, companion-order, event and retry screenshots inspected. Graphify refreshed (3178 nodes/8385 edges/153 communities).

Browser late-story gates use a named disposable local D1 progress/ownership fixture; they do not prove a late-story playthrough, gacha-free acquisition of Kera or final balance. C3 retains the separate real first-chapter Iona/manual no-gacha proof. No canon, amounts, paid media, live resources or player history are repaired. R08 effective catalogs/full grammar/version negotiation, R09 continuity, R12 event schedules/rewards/modes, R16 balance/production media and R18 unchanged-AAB/native/deployed acceptance remain open. Voice relationship/bestiary surfaces must apply the canonical spoiler policy when introduced; combat intents do not receive lore.
