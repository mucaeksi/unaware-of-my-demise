## 4. Recommended path

1. **Stabilise staging** (#1) — done when `/api/v1/characters` returns 200 on the redeployed tag.
2. **Close the core loop:** pace probe (#3, done) → owner target → XP/AFK/material tuning → the six missing mode screens (#2). This turns "the server can" into "the player can", with a measured pace for "level 20 is hard to reach".
3. **Owner decisions that unblock content:** target pace (#3), combat semantics list (#7), economy tuning (#6), signature weapon effects (#5, with Argon).
4. **Content fixes by Argon:** missing banners (#4), signature effect designs (#5), then the art pilot through `tools/ingest_art.ts`.
5. **Debt:** waves in the builder (#8), paged screens (#9), phone/tablet e2e and device runs.

Why this order: the skeleton is broad and mostly sound; what is missing is the client surface for half of the progression systems and the numbers that tie them together. Visual work does not depend on either, so Argon can continue assets in parallel.
