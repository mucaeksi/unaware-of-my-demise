# uomd-design-system

Read current project context, relevant design/architecture/decision docs and source behavior. State summary, player need/fantasy, detailed rules/states, dependencies, edge cases, tuning knobs, visual/audio/UI requirements and testable acceptance criteria. Include formulas with defined variables only where the actual design needs them. Cross-reference existing entity IDs and interfaces; do not invent canon, budgets or replacement architecture. Work only on the owner's requested presentation scope. Combat AI, economy, summon algorithms and progression capabilities remain deferred.
